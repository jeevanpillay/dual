# devcontainer.json as Primary Config Source

## Context

The current implementation treats devcontainer.json as a fallback when `.dual.toml` is missing. The user wants the opposite model: devcontainer.json is the **primary source** for container configuration, and `.dual.toml` contains only Dual-specific orchestration fields. This aligns with the devcontainer ecosystem — users define their container in devcontainer.json, and `.dual.toml` handles only what devcontainer can't (command routing, shared files, volume isolation).

**Breaking change**: Fields `image`, `ports`, `setup`, `env` are removed from `.dual.toml`. Users must move container config to `devcontainer.json`.

## New Config Model

**`.dual.toml`** (Dual-specific only):
```toml
# devcontainer = ".devcontainer/devcontainer.json"  # auto-detects if omitted
extra_commands = ["cargo", "go"]
anonymous_volumes = ["node_modules", ".next"]
[shared]
files = [".env.local"]
```

**`devcontainer.json`** (container config):
```json
{
    "image": "node:20",
    "forwardPorts": [3000],
    "postCreateCommand": "pnpm install",
    "containerEnv": { "NODE_ENV": "development" }
}
```

**Loading flow**: `.dual.toml` (DualConfig) + `devcontainer.json` (DevcontainerJson) → merged `RepoHints`

## Phase 1: DualConfig Struct + New load_hints()

### 1a. Add `DualConfig` struct to `src/config.rs`

```rust
#[derive(Debug, Serialize, Deserialize, PartialEq, Clone)]
pub struct DualConfig {
    #[serde(skip_serializing_if = "Option::is_none")]
    pub devcontainer: Option<String>,
    #[serde(default)]
    pub extra_commands: Vec<String>,
    #[serde(default = "default_anonymous_volumes")]
    pub anonymous_volumes: Vec<String>,
    #[serde(skip_serializing_if = "Option::is_none")]
    pub shared: Option<SharedConfig>,
}
```

`RepoHints` stays unchanged — it's the internal merged representation all consumers use.

### 1b. Rewrite `load_hints()` (config.rs:117-136)

New flow:
1. `load_dual_config()` — reads `.dual.toml` → `DualConfig` (defaults if missing)
2. `resolve_devcontainer_path()` — uses explicit path from DualConfig or auto-detects
3. Parse devcontainer.json → `to_repo_hints()` for container fields
4. `merge_config()` — DualConfig fields + devcontainer RepoHints → final `RepoHints`

Add migration warning: if `.dual.toml` contains `image =`, `ports =`, `setup =`, or `[env]`, log a warning telling user to move to devcontainer.json.

### 1c. Update `write_default_hints()` → `write_default_dual_config()` + `write_default_devcontainer()`

- `write_default_dual_config()` — writes `.dual.toml` with only extra_commands, anonymous_volumes, shared (all commented)
- `write_default_devcontainer()` — writes `.devcontainer/devcontainer.json` with `{"image": "node:20"}` (valid JSON, no comments)

### 1d. Add `write_dual_config()` and `parse_dual_config()` helpers

For tests. Keep old `write_hints()`/`parse_hints()` temporarily but mark unused.
